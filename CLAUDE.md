## Project Overview

Design Book is a reactive TypeScript design system framework for managing tokens (colors, spacing, typography) with dependency tracking, dynamic calculations, and multi-format rendering. Uses Culori for color operations.

## Architecture

### Core Classes

- **DesignBook** (`src/design-book.ts`) — Central orchestrator. Owns ScopeManager, DependencyGraph, typed event emitter, function registry. Supports `auto` (immediate propagation) and `batch` (deferred via `flush()`) modes. Re-entrant-safe in auto mode. Built-in functions auto-register in constructor via `registerBuiltinFunctions()`. `inspect(key)` bundles value, token shape, graph neighbours and provenance; `picked` is the member a selector picked when the value is that member's (`capturePick` around the resolve; also through refs; absent when computed from it).
- **Scope** (`src/scope.ts`) — Named token container with inheritance via `extends`. Resolves tokens: basic values, references (cross-scope via DesignBook), and functions (looked up from DesignBook's function registry by `fn.name`, not stored on the token). A pool is stored as a scope reference (`ref('palette')`) and looked up by name at resolve time (`resolveArg` hands the implementation the live `Scope`), so a selector follows a scope that was deleted and re-created. Supports `hasOwn()`, `isInherited()`, `getSourceKey()`, and `delete()` for inherited token management. `addScope(name, { metadata })` attaches a free-form plain object (`scope.metadata`, default `{}`, shallow-copied, mutable, not inherited through `extends`); the book never reads it — only the css-variables renderer reads `metadata.media`. `set()` validates the key (`assertValidTokenKey`): only ASCII letters, digits, `-`, `_` and non-ASCII characters, so whitespace, `.`, `$`, `{`, `}` and other punctuation throw a `TokenError` — keys end up in CSS custom-property names and W3 token names. `detectValueType()` (exported from `src/scope.ts`) is the one rule for typing a resolved value, used by Scope ordering and the W3 renderer: Culori-parseable → `color`; a single number with an optional unit (`16px`, `.5rem`, `1.5`) → `dimension` (unitless = empty unit, like `dimension(1.5, '')`); anything else (`16px solid`) → `string`.
- **ScopeManager** (`src/scope-manager.ts`) — CRUD for scopes, tracks inheritance (a children map: `lineageBelow(name)` is the scope and every scope extending it, which the pool fan-out reads). `getScopeDependencies()` checks both reference and function token dependencies. `deleteScope(name, notify)` hands the book all removed keys with their tokens at once (the book announces them as one change).
- **ResolveCache** (`src/resolve-cache.ts`, `book._cache`) — memo of resolved values per qualified key, with the pick each computation reported (replayed on a hit). Cleared on every change that can move a value (token write / delete / rollback, scope order, scopes added or removed, a function, orderer or ramp set registered); not kept while the re-entrancy guard tripped (`trip`) or while a scope sorts (`without`). Its `generation` (bumped per clear) stamps what is derived from values: a scope's sorted keys (`orderedKeysCache`) and a scope ramp set's engine — no listeners, no descendant walks.
- **DependencyGraph** (`src/dependency-graph.ts`) — Extends generic `Graph` (`src/graph.ts`). Tracks *value* dependencies only, and prevents circular ones at write time via `updateEdges()`. Inherited tokens register a dependency on their source key. Selector candidate pools are deliberately **not** edges — see "Selector pools" below.

### Token System (`src/tokens.ts`)

Three value types: `TokenValue`, `ReferenceValue`, `FunctionTokenValue` (union: `AnyTokenValue`). References come in three types: `ReferenceValue` (`type: 'reference'`, a value or a pool; `inherited` as `up`), `MemberReference` (`type: 'member'`: names a token rather than reading it — a `not` entry, a `sibling` anchor / `toward`, a variant's `base`; `source` / `refersTo` build one, `toMember` / `toMembers` turn keys and refs into them; a member slot (`MEMBER_SLOTS`: `not`, `from`, `toward`, `base`) only ever holds member references) and `UnresolvableValue` (`type: 'unresolvable'`, what a navigation binds to when it runs past the top of a chain). One walker (`walkRefs`) visits every reference in a token and says where it sits (value or member slot); binding, traits, dependencies, `unresolvableIn` and `misplacedSource` are built on it.

**Key design**: Tokens are pure serializable data. No closures or functions stored on token objects.
- Processors (e.g., Culori parsed color instances) live in `WeakMap` via `getTokenProcessors()` / `setTokenProcessors()`
- Function implementations are looked up from the DesignBook registry by `fn.name`, not stored on `FunctionTokenValue`

Constructors — all validate and throw on invalid input:
- `color(value)` — any CSS color via Culori
- `ref(key)` — a path: `'scope'` (a scope, valid only as a pool), `'scope.token'`, `'scope.token.field'`; relative with a leading dot (`'.'` = the reading scope, `'.token'`, `'.token.field'`) — see "Relative refs" and "Navigation" below
- `inherited(ref, levels = 1 | 'root')` — the same reference further up the **`extends` chain** (the scope tree); stored as `ref.up` (a number or `'root'`)
- `source(ref, hops = 1 | 'root')` — the token a reference refers to, along its **references** (the value tree); stored as `ref.via`. Only read where a member is named (a `sibling` anchor / `toward`, a `not` entry): followed `hops` plain refs, or to the first token that is no ref (`'root'`); a selector's pick is never looked through; more hops than there are throws. Refused as a value or inside a value argument (`misplacedSource`, checked in `Scope.set`) and on a scope key. Composes inheritance first: `source(inherited(ref('.x')), 'root')`
- `refersTo(ref)` — the other way down the value tree: the members of the walked pool whose plain refs lead to the token (any depth, selectors not looked through); stored as `ref.referredBy: true`, read where `source` is (`isMemberReference` / `memberReference` keep both markers through binding). `referrersIn` / `oneMember` in `src/functions/members.ts`: a `not` entry excludes every referrer, a `sibling` anchor / `toward` needs exactly one (else throws listing them), none throws; a `sibling` anchor needs the scale named. `source` / `inherited` are read first (`refersTo(source(…))`); `source(refersTo(…))` throws. A bare `refersTo` adds no graph edge (the pool index covers it)
- `px(n)`, `rem(n)`, `ms(n)` — dimension shortcuts, delegate to `dimension(n, unit)`
- `dimension(n, unit)` — generic dimension
- `string(value)` — string token
- `createFunctionToken(name, args, config?)` — creates `FunctionTokenValue` without needing to specify `type` or `rawValue`

Type guards: `isReferenceValue(arg)`, `isTokenValue(arg)`, `isScopeReference(arg)` (a reference whose key is a scope path, `isScopeKey`)

Function argument type: `FunctionArg = TokenValue | ReferenceValue | FunctionTokenValue | string | number` — no `Scope` objects: a selector constructor takes `PoolArg = ReferenceValue | Scope` and stores a scope object as `ref(scope.name)` (`poolArg` in `src/functions/args.ts`), so a function token is always plain data. `poolArg` takes only a `ref('scope')` or a real `Scope` (`instanceof`; a scope-shaped object is refused, since only its name would be kept) and refuses a token reference; `valueArg` (used by the value constructors) refuses a scope reference.

### Relative refs (`ref('.token')`)

A leading-dot key reads that token in the scope that *reads* the token, so an inherited `button.hover = shade(ref('.bg'))` reads `button-danger.bg` in `button-danger extends button`. Tokens keep the relative form (shared data — an inherited token is one object); `bindToken(token, scope)` (`src/tokens.ts`, cached per token × scope so identity is stable) qualifies ref keys, nested args, `options.from` / `base` / `not`, `metadata.dependencies` / `visualDependencies`, and an `iteratedScopes` entry of `''` (a relative `sibling` anchor). Binding also follows `inherited` (`up`) through a `BindingContext` the book supplies (`parentOf`, plus a `version` bumped on every add / delete scope so a cached navigated binding never outlives its chain); a navigation past the top binds to an `UnresolvableReference` (`unresolvable: message`) that adds no edge and throws when resolved — `Scope.set` refuses it up front (`unresolvableIn`), as it refuses a scope reference in value position. `extractDependencies` skips scope refs and not-yet-bound navigated refs (their edge comes from the bound args). `Scope.get` returns the **bound** token; `Scope.getRaw` the token as written — use `getRaw` for identity checks (`_ownToken`, layer provenance), copies (`copyTokensInto`) and serializing (editor). Everything else (resolve, graph deps, renderers, reference cache) sees bound tokens and never a relative key; `book.resolve('.x')` throws.

**Inherited keys are wired like own keys, as soon as they exist** (one mechanism). A plain one (`_readsSource(key)`: inherited and not re-bound) has one edge, to its source key; one whose token has relative keys is **re-bound** (`book.isRebound(key)`) and gets the token's dependencies as its scope binds them. `_wireShadows(key)` runs inside every write / delete / rollback of a key (auto and batch, via `_wire`) and re-wires the key's copies in every scope below (`lineageBelow`), unwiring copies that no longer exist; `addScope` wires everything the new scope inherits (`_wireInherited`). It returns the re-bound copies (they change with the token but have no edge to it), which are announced with the key; plain copies are reached through their edge. A re-bound copy can close a cycle that exists only in its scope: `_wireInherited` undoes all and throws, so the `set` is refused, `Scope.delete` restores the token (`_restoreRejectedDelete`), and `addScope` discards the scope (`_discardScope`). A node stays while its key exists (`has`), own or inherited. A pool can be relative (`ref('.')`, `inherited(ref('.'))`): `extractIteratedScopes` reads scope refs (`'.'` → `''`, bound to the reading scope), so the selector index sees the bound scope name. `sibling` / `variant` keep a navigated anchor / base as the reference in `options.from` / `options.base` (constructors add no edge for it); `bindToken` turns it into the key it lands on and adds that key to `metadata.dependencies` (and, for `sibling`, its scope to `iteratedScopes`). A `source` reference (`via`) in `from` / `toward` / `not` is bound (qualified, `up` followed) but stays a reference `{ key, via }`: it is followed only when the function resolves, and adds no `iteratedScopes` entry. The typography helpers read the base through `baseKeyOf`, which only accepts a bound (string) base.

`DependencyGraph.updateEdges` checks cycles locally (does `key` already reach a new prerequisite?) and `_setEdges` tracks only nodes it may create — both used to walk / copy the whole graph per write.

### Naming (`src/naming/`)

Published twice: from the package root and as the standalone subpath `design-book/naming` (second Vite lib entry → `dist/naming.js`, types at `dist/naming/index.d.ts`). It must stay dependency-free — it may import only `src/errors.ts` and `src/keys.ts` (the token-key check, re-exported by `scope.ts`); `tests/naming/standalone.test.ts` enforces this.

`nameValues(values, scheme, options?)` (→ `[name, value][]`), `scaleNames(count, scheme, options?)`, `nameBetween(lower, upper, scheme)`, `namingScheme(names, { base?, anchor? })` and the frozen `schemes` record produce token **keys** only — they never create or touch values or a DesignBook.

A scheme is a vocabulary (kinds: `list`, open-ended `ordinal` / `roman` / `tshirt`, numeric `range` with coarse-to-fine step tiers, and `value`, which names each value by its own number and so only works through `nameValues`) plus a default strategy, reported as `anchor`. Strategies: `start` (consecutive from `from`, by `step`), `base` (consecutive both ways from a centre), `range` (ends fixed, spread evenly; a pinned `[n, name]` spreads each side to its end; lists with a centre name pin it by default, in proportion). Without `anchor`, a bare `base` index implies `base`; a `[n, name]` pin implies `range` on bounded vocabularies and `base` on open-ended ones. Ranges over open-ended vocabularies need `from` and `to` and are spread as a materialised list.

- `overflow: 'between'` (range, and start on a list) keeps every name and fills extra steps as fractions (`fillGaps`: `soft_5`, `low_33 low_67`); numeric ranges keep halving their step (`62_5`).
- `nameBetween` maps names to positions (list index, t-shirt offset, Roman value, the number) and returns the name at the midpoint: a real name when one sits there, else `<name below>_<fraction>`; it accepts its own output. The docs steer users to re-run `scaleNames` and use `nameBetween` only when existing keys must stay stable.
- Options that do not fit the scheme and strategy throw. Number names are keys: `0_25`, `-1`. Every name passes `assertValidTokenKey`.

### Functions (`src/functions/`)

Each function exports a **constructor** (returns `FunctionTokenValue` via `createFunctionToken`) and an **implementation** (the actual computation). Implementations are auto-registered on DesignBook construction via `registerBuiltinFunctions()`.

Constructors refuse option keys they do not read (`assertOptions` in `src/functions/args.ts`, `READABLE_OPTIONS` shared; `description` always allowed; stored tokens are not re-checked) and validate every static option up front, throwing `FunctionError` (fractions, color spaces, `relativeTo` modifications, the scales' numbers, `nth`'s index, `random`'s type and seed, `minContrast`, directions).

One contract (`src/functions/index.ts`): at resolve time `Scope.resolve()` calls `implementation(...resolvedArgs, resolvedOptions)`. Options that hold a reference, token or function token are **inputs**, resolved like arguments (`Scope.resolveInputs`: `readableOn`, `closest`'s `upTo`); member slots are passed as written. A selector's `not` is read against its pool by the registry (`excludedMembers`), so a selector implementation receives qualified keys. `registerFunction(name, impl, traits?)`: `FunctionTraits.scopesRead(token)` names scopes a token reads that only the book can work out — `sibling` with a `source` anchor, `ramp` reading scope masters; the selector index adds them and `_reindexDynamic` asks again on every notification. The book names no built-in function.

A function token's graph edges are `functionDependencies(fn)` (`src/tokens.ts`): the value refs in its args and options (nested tokens included), the start keys of `from` / `toward` / `base` members, `not` entries outside its iterated scopes, unioned with `metadata.dependencies` — so a bare `createFunctionToken(name, [ref(…)])` is tracked too. The book-internal helpers (binding, dependency extraction, `DependencyGraph`, `registerBuiltinFunctions`) are exported from `design-book/internals` (`src/internals.ts`, its own Vite entry), not the root.

**The pool** (`src/functions/pool.ts`): every selector resolves its pool (`resolvePool`), keeps the target's kind, narrows, and keeps the best (`best`, ties to the first member). `colorPool` (colors in their compared forms, computed once per string by `colorForm`; then the `readableOn` filter), `measuredPool` / `measureOf` / `ofKind` for sizes and text styles, `describeKind` for messages. Color math (contrast, gamut mapping, distances) is in `src/functions/color/color-math.ts`.

**Comparisons, any kind** (`src/functions/kinds.ts`): `closest` (`src/functions/generic/closest.ts`) with the aliases `nextLarger` / `nextSmaller` / `nextLighter` / `nextDarker` (they build the same `closest` token with `options.direction`; the editor prints a `closest` with a plain direction and no `upTo` as its alias), `bestContrastWith`, `minContrastWith`, `furthestFrom`, `largest` / `smallest` (`generic/extremes.ts`), plus `lightest` / `darkest` for colors. The *target's* resolved value decides the kind (`measureOf` / `kindOf`): a color, a size (`num` + unit), or a text style (resolved `typography()` declarations, measured by `font-size`). Only members of that kind — and for sizes / text styles the same unit — are compared (`measuredMembers`); others are skipped. Directions are type words (`lighter`/`darker` colors, `larger`/`smaller` sizes and text), checked at construction (`assertDirection`) and against the kind at resolve (`assertDirectionFits`). A text style is measured by one field, `by` (default `fontSize`, `DEFAULT_MEASURE_FIELD` in `src/values.ts`; `measureOf(value, by)` / `measuredPool(scope, not, by)`; checked by `byOption`; on `closest` + aliases, `furthestFrom`, `largest` / `smallest`, the contrast pair); any numeric field measures, a style without it is no candidate; sizes and colors ignore it. A color field works on every color comparison (`colorPool(…, by)`, `colorValueOf(value, by)`; `ColorMember.value` is what a pick returns: the hex for a color, the whole style for a text style; `mostVivid` / `leastVivid` / `lightest` / `darkest` declare no `returnType` when given `by`). A scope's `{ by: 'value', field? }` ranks text styles by that field with the orderer of its kind (`Scope.valueRanks`, one ranking per value criterion, entries of different groups not compared). A color-returning function handed a whole text style throws naming the field to pass (`Scope.assertNoTextStyle`). Contrast for sizes / text is the ratio of the larger to the smaller value (`measuredContrast`); `minContrastWith` / `bestContrastWith` take `direction` for every kind. `furthestFrom(target, pool, { maxDistance })` (`generic/furthest-from.ts`) is `closest`'s mirror, by the same measures: the furthest member, or with `maxDistance` (OKLab distance / the target's unit) the furthest one within it. Targetless functions (`largest` / `smallest`) use `onlyMeasuredGroup` (one kind+unit group, or `{ type }`, else throw). `readableOn` is color-only.

**Color only**: `mostVivid`, `leastVivid` (both take `lightness: [min, max]`, an OKLCH L band the pool is narrowed to first, `src/functions/color/lightness-range.ts`)

**Positions** (generic selectors): `nth`, `random`

`nth` index: integers (including `1.0`, which *is* `1`) are direct indices, negative ones count from the end (`-1` = last); only non-integers are relative positions (`0.5` = middle), clamped to [0, 1].

The generic selectors (`nth`, `random`, `sibling`) and the measured comparisons build their pool through `src/functions/scope-members.ts` (`poolKeys` / `resolvePool`), so they agree on positions: `not` matches a member's qualified key or, for an inherited member, its source key (after the registry has mapped each entry to pool members with `excludedMembers` in `src/functions/members.ts`: a `source(…)` entry is followed first (`memberStart` / `followSource`); then a key of the pool stays as is, the key an inherited member comes from names that member, and any other entry names the first key its plain refs lead to inside the pool (`landIn`) — or, where they end on a selector, the member it reports having picked (`capturePick`) when that member is in the pool; a member that refers to the entry is not matched; a `refersTo(…)` entry names every member whose plain refs lead to it; an entry that names nothing throws — `not` entries outside a token's iterated scopes, and a `source` entry's start key, are graph edges via `notDependencies` in `functionDependencies`); members that themselves walk the scope (`iteratedScopesOf(tok)` includes it — selectors, nested ones, `sibling`) are skipped; unresolvable members are skipped. Color selectors share only the `not` rule (`isExcluded`).

**Steps along a scale**: `sibling(ref, scope?, steps = 1, { toward, wrap, not })` — keeps the anchor in `fn.options.from` (a key, or a reference with `up` / `via`; the target likewise in `options.toward`). **The scale is never guessed**: by default the anchor's own scope (declared in `metadata.iteratedScopes`; `sibling(ref('space.s'), 1)` walks `space` even when `space.s` refers elsewhere); with a scope argument (stored as the function's arg, so the selector index sees it) that scope, the anchor's plain refs followed until they land in it, or a selector they end on counting for the member it picked when that member is in it (`landIn`, refused otherwise) — so `sibling(ref('.text'), ref('scale'), 2)` steps from whatever `.text` picked; with a `source(…)` anchor, wherever its refs lead (`followSource`). `toward` and `not` are read against the walked scale by the same rule as `not`. The walk takes `toward`'s direction, stops on it, and a negative count walks away. Only a `source` anchor's scale is known just at resolve time: `sibling`'s `scopesRead` trait follows it, so the selector index has it. Selectors report their pick (`picked` / `capturePick` / `inFrame` in `src/functions/picks.ts`; each call in its own frame so a pool member that is a selector cannot overwrite the caller's report): `landIn` reads it, only against a scope the author named, and the SVG renderer reads it to draw edges. Without a named scale `sibling` never asks. The editor serializer special-cases it back to `sibling(ref('…'), ref('scale'), n, { toward })`.

**Without scope** (pure transforms): `colorMix`, `lighten`, `darken`, `shade`, `relativeTo` (three channel slots plus alpha), `withAlpha` (= `relativeTo(x, 'rgb', [null, null, null, a])`, sets alpha; the editor prints it back via `withAlphaOf`), `spacingScale`, `typographyScale`, `timing`

**Ramps** (`src/functions/color/ramp.ts`): `ramp(seed, { shade, from? })` / `rampStops` copy a set of master ramps via dittotones. The book keeps named sets (`registerRamps(name, set, { default? })`, `colorRamps` option, `rampSetNames`; built-in `tailwind-v3` from `dittotones/ramps/tailwind-v3`): a fixed `RampSet` (`rampSet()` builds one from any CSS colors: at least two ramps, all the same length and shades) or a list of at least two of the book's scopes read live (`_masterRamps`; the engine is reused while the resolve cache's generation is unchanged, then re-read and kept if the masters' colors are the same; a master copying its own set throws). `ramp`'s `scopesRead` trait names the set's master scopes (`rampMasterScopes`), so a change in a master fans out through the selector index like a pool, no graph edge; re-registering a set re-indexes its readers (`_keysByFunction`) and announces them (`_announceRampSet`). Tokens store only the set name.

**Composite**: `typography(fields)` (`src/functions/non-color/typography.ts`) — a text style as one token (W3 `typography`). The field values are the args, the names `options.fields` (each a valid token key), so field refs are ordinary graph edges and a `ref()` to it carries the whole style. Resolves to `font-size: 2rem; line-height: 1.5` (fields kebab-cased, in order). `ref('scope.token.field')` reads one field (`isFieldKey` / `tokenKeyOf` in `src/tokens.ts`; at most one field level). The graph keeps **field nodes**: a typography depends on one node per own field, each field node on what that field reads (`typographyFieldDependencies`) — a variant's inherited field on the base's field, a field read through a ref on the target's field, a shadow's on its source's, anything else on the token. `DesignBook._setEdges` sets a token's and its field nodes' edges as one step (fields cleared first; a cycle restores all and returns/throws); `_collectDependents` walks a token's field nodes but never reports them; `_pruneOrphans` drops unread field nodes; `inspect` looks through own field nodes, answers for field keys (`tokenType: 'field'`, `owner`, `field`), and the SVG renderer maps field nodes to their token's row. So a field may read a sibling field and two styles may read each other's other fields. `Scope.resolve` / `DesignBook.has` handle the third segment (following refs and variant bases); a variant whose base is gone throws in every format; CSS gets `var(--scope-token-field)` for free; W3 writes the resolved field (no alias syntax inside composites). `variant(base, overrides)` (`null` drops a field): with a **token** → a copy (how a layer changes a style in place); with a **ref** → a live variant (`options.base`, plus `options.removed`; the base key is in `metadata.dependencies`), whose unset fields read the base — `typographyFieldNames()` gives the full list, the registry closure needs `resolve` / `getTokenByKey`, and `Scope.set` rejects a variant of its own key with a hint. The css-variables renderer writes `--scope-key-<field>` per field plus a `.scope-key` class, for the token and for any ref (chain) ending at one (`var(--target-<field>)`); a variant's inherited fields are `var(--base-<field>)`; the collision check covers field variables. W3 writes the native composite (fields resolved); a ref to it stays an alias with `$type: typography`. The editor parses and prints `typography({ … })` and `variant(ref('…'), { … })` (`serializeTypography` in `site/editor/editor.ts`, `parseFieldObject` in the input parser).

#### Selector pools (`_selectorsByScope` in `src/design-book.ts`)

A selector's candidate pool is the live membership of the scope it iterates.
That is not a value dependency — a pool member may legitimately be derived
from the selector itself (`ui.muted = lighten(ref('ui.text'))` where
`ui.text` selects out of `ui`) — so pools live in an index (scope name →
selector keys, with the reverse map `_scopesBySelector`) rather than in the
graph, which would reject that write as a cycle. `_indexSelector` maintains
it on every write, delete and rollback; `_collectDependents` fans out
through it so a change to any key of scope S (own or inherited, added,
changed or deleted, resolved along the `extends` chain) notifies every
selector iterating S and then continues the normal DFS. Mutual pools
terminate on the `seen` set; a selector never notifies itself.

#### Color behaviour worth knowing

- Selectors judge translucent candidates composited over the target and can return 8-digit hex.
- Selector pools (`colorPool`) gamut-map wide-gamut members in OKLCH like the transforms do, rather than clipping them.
- `readableOn` + `readableContrast` (default 4.5) filter a color selector's pool by WCAG contrast before ranking (`src/functions/color/readable.ts`), on every color selector including `bestContrastWith` / `minContrastWith` (there it is a second background; `minContrastWith`'s own threshold is `minContrast`, kept apart). The backdrop is an input option, resolved like an argument, so it is a value dependency; an empty filtered pool throws; a size / text target with `readableOn` throws.
- `lightest` / `darkest` rank by OKLCH L, ignoring alpha.
- `closest` takes `direction` or `upTo` (a value, an input option), plus `minDistance` (OKLCH L gap): only members strictly on that side of the target's lightness count, `upTo` no further than its lightness.
- `closest` / `furthestFrom` measure colors by Euclidean distance in OKLab. Translucent colors are compared composited over the `readableOn` backdrop, or without one over both white and black, taking the larger distance (`visibleDistance` in `color-math.ts`).
- `lighten` / `darken` are OKLCH mixes towards white / black through `cssColorMix` (`src/functions/color/color-mix.ts`) — the JS twin of the `color-mix()` the CSS renderer emits, premultiplied alpha included. `colorMix` uses the same helper. `shade` shifts OKLCH lightness and carries alpha through; `relativeTo` carries it through too. All gamut-map in OKLCH before formatting and emit 8-digit hex only when translucent.
- Size comparisons skip members whose unit differs from the target's instead of throwing.

### Renderers (`src/renderers/`)

- **Renderer** — Outputs CSS variables (with `var()` refs, `color-mix()`, `calc()`, `color(from ...)`), JSON (resolved values), or W3 Design Tokens (structured objects per spec with proper color/dimension/duration formats). Built-in function renderers auto-registered in constructor. The CSS pass throws when two keys mangle to the same custom-property name. A `typography()` token is a W3 `typography` composite in its own scope; a `ref('scope.token.field')` emits the resolved field (with `fontWeight` / `fontFamily` / `dimension` / `number` `$type`) instead of an alias W3 cannot express. There is no scope-level typography (`addTypography` / `compose` were removed). W3 `dimension` is emitted only for `px` / `rem` (`ms` / `s` → `duration`, unitless → `number`); other units (`em`, `%`, `vw`, …) have no W3 type, so they get no `$type` and keep their CSS text as `$value`, like a string — inside typography composites too. Colors are gamut-mapped into sRGB before their components are read. `$type` can be overridden per token with `metadata.w3Type`; because `val()` shallow-merges options, pass `metadata: { unit, w3Type }` in one object or the constructor's `unit` is lost.
- **Registry and entries** — the book keeps no renderer imports: `book.render(name)` reads the book's own `registerRenderer` map, then a shared one (`useRenderer(name, fn)` in `src/design-book.ts`). `src/index.ts` (`design-book`) re-exports `src/engine.ts` and calls `registerBuiltinRenderers()` (`src/renderers/builtin.ts`) on import; `design-book/engine` (`src/engine.ts`, its own Vite entry) is everything else, with no renderer module reachable (`tests/engine-entry.test.ts`). Tests register the built-ins in `tests/setup.ts`. The build keeps `culori`, `dittotones` and `colorsort-js` external (dependencies), except `colorsort-js/trained.json`, which is bundled (a bare JSON import needs an import attribute).
- **Variations** — themes, inverted contexts, brands and breakpoints are separate books built by the same setup function; nothing about conditions is stored in a book. css-variables takes `selector` (default `:root`), `media`, `breakpoints` (name → query; a scope whose `metadata.media` is a breakpoint name, a media type or a raw query renders in its own `@media` block — blocks in table order, then raw queries in scope order; an unknown bare name throws), `scopes` and `changedFrom: otherBook` (only declarations whose rendered text differs, so `var()` references are skipped and recomputed values kept; typography classes are skipped). json takes `scopes` and `changedFrom` (resolved values). `diffBooks(a, b)` (`src/diff-books.ts`) returns `{ changed, added, removed }` by resolved value.
- **Layers** (`src/layers.ts`) — `layer(name, fn | data)` and `composeBook(name, layers, options?)`: a theme is a sparse layer, a themed book is a stack applied in order (last wins) into one plain book, so root overrides re-flow through the normal `set` path. No core changes; nothing about layers is stored in the book. Built in batch mode with a `flush()` per layer; a thrown error or a rejected cycle becomes a `LayerError` (`layerName`, `tokenKey`, `cause`). Data layers create missing scopes, accept tokens only and deep-clone them (tokens are plain data, pools included). Provenance (`layerOf`, `keysFromLayer`) lives in a module `WeakMap`, computed by diffing own-token identity before/after each layer. Scope `extends` is not a whole-system theming tool — inherited absolute refs keep their original keys; relative refs (`ref('.x')`) re-bind within the inheriting scope, for side-by-side variants in one book.
- **SVGRenderer** — `layout: 'layered'` (default): tables in columns by data flow (`scopeFlow` counts token reads between scopes, `extends` included; `layOutInLayers`: cycles broken by a DFS, longest-path layers, barycenter ordering sweeps, column gaps sized by the lines crossing them, columns centred); a row reads on its left edge and is read on its right one (ports `key:in` / `key:out`; a row read from another table gets a left dot too), a read within one table keeps both ends on the right. A scope extending a drawn scope is joined under it (`TableInfo.parent`; the family is one block, one width, no `extends` line, reads within it on the right like reads within a table) and shows only what differs (`differingRows`: own rows, re-bound rows whose value differs from the parent's, rows read or picked from outside the family, and rows those read), the rest in one row `+N from parent`. The layout places blocks: lines skipping columns get placeholders (gaps kept in the columns between), barycenter ordering, then every block moved level with its neighbours by pool-adjacent violators; `scopeFlow` counts only lines the renderer draws (`linksOnly`, `filterConnections`); cycles are broken heaviest edge first; `aspect` (default 1.5, width / height the graph is shown at) steers the choices: a column far taller than the shape is wrapped in two (the blocks with most lines to the right stay inner), blocks with no line to another go in a row above or columns beside, whichever is nearer the shape; levelling stays inside the tallest stacked column; `scopeFlow` counts rows with a line to a scope, not lines (lines from one row bundle); column gaps are a margin each side plus a lane for about three in four crossing rows, at most 16 lanes, at least two rows. The article passes its sheet's shape. `layout: 'circle'`: the ring, dots facing inward. Connections are routed orthogonally round the tables by default (`routing: 'orthogonal'`; `'curved'` = the old Bezier per edge) by `OrthogonalRouter` (`src/renderers/orthogonal-router.ts`), libavoid-style in two passes via `routeAll`: A* over a sparse grid (table edges plus `margin`, gap middles, port rows, stub ends; tables closed, bends costed; a segment used only by routes sharing a dot is cheap so they bundle, unrelated users add a capped crowding cost, runs along a table's side cost more so lines turn in the open), then nudging: runs on one grid line join a lane when they overlap and share a dot; overlapping lanes within a few lane gaps are spread together `laneGap` apart, ordered by line and by how their ends turn, placed nearest their line (pool-adjacent-violators), runs on a port's row fixed, clamped to the free space. Routed in connection order; an unroutable edge falls back to the curve. `bridges` (default true): where two same-colored lines cross, the horizontal one hops (`bridges()` / `roundedPath`; one hop per crossing spot, close ones merged, the line underneath drawn first); interactive SVGs also carry a flat copy (`conn-flat`) shown while a token is hovered. Where lines sharing a dot join or split, a small dot (`conn-junction`, `junctions()`), except within a stub of the line's own dot. `filterConnections(from, to)` drops connections before routing (keys as in `data-from` / `data-to`), so dropped lines hold no lanes and get no bridges; the tour uses it to keep only the ramp's anchor edge to `brand.primary`. Dashed lines for function dependencies. A token is a palette-linker only when it iterates a scope itself — a top-level scope arg or its own `metadata.iteratedScopes` (`sibling`) — so a selector nested in a value deriver doesn't hide the outer token's graph edges. The pool is read live from the book, not from the construction-time `metadata.visualDependencies` snapshot; the edge comes from the member that matches the output (never the token itself), and a linker with no matching member falls back to its graph edges. Inherits CSS variables from the editor for theming.

### Editor (`site/editor/`)

Interactive CodeMirror 6-based editor. One CodeMirror instance per scope. Features:
- Context-aware autocomplete (refs, scope names for scope-arg functions, functions, value constructors, `inherit` keyword)
- Inline color swatches (editable via `hdr-color-input` picker for `color()` tokens, read-only for `ref()` resolved colors)
- Error highlighting (wavy red underline for unparseable lines)
- Inherited token dimming (opacity 0.4) with `inherit` keyword support
- `inherit` keyword shows resolved value inline as `→ #0066cc`
- Empty scopes removed on blur
- Inherited keys auto-re-injected if deleted from editor

### Typed Events (`src/design-book.ts`)

Event system uses `DesignBookEventMap` with typed payloads:
- `tokenChanged` → `TokenChangedDetail { key, cause, newValue, oldValue, value }` — one shape on every path (`_emitTokenChanged`): `cause` `'written'` (the stored token was set / deleted; `newValue` / `oldValue` the tokens after / before) or `'dependent'` (token unchanged, both the same token); `value` the resolved string or `undefined`. `watch` passes `value`.
- `change` → `ChangeDetail { changedKeys, scopes }`
- `scopeAdded` → `ScopeAddedDetail { scope }`
- `scopeRemoved` → `ScopeRemovedDetail { scope, removedKeys }`
- `batch-complete` → `BatchCompleteDetail { processed }`
- `batch-failed` → `BatchFailedDetail { processed, errors }`

`on()` and `watch()` return unsubscribe functions.

### Key Design Decisions

- All token keys are fully qualified: `"scope.token"` — except relative refs (`".token"`) inside tokens, which are bound to a scope before anything reads them
- Tokens are serializable data — no closures, functions, or mutable state on token objects
- Function implementations live in a registry, looked up by name at resolve time
- Token `type` field is `string` (not a union) — extensible for custom types
- `flush()` does not throw — collects errors, fires `batch-failed`; its result (and the event) list `rejected`, the writes the graph refused and rolled back
- A write is wired into the graph, inheritance links and selector index by one method, `_wire`, in auto mode and in `flush` alike (undone and thrown when refused); `_rollbackKey` is the lenient twin that restores an accepted state
- Setting `mode` from `batch` to `auto` flushes whatever is still queued
- A write is checked and wired when it is made (`_accept` → `_wire`), before it is announced (`_settle` → `_announceChange`): a refused write throws from `set()` / `delete()` and was never announced; the scope puts the old token back. There is no corrective announcement and no `error` event
- `addScope` rejects empty/dotted names and self- or cyclic `extends` with a `ScopeError`
- Circular dependency errors in batch mode are collected, not silently swallowed
- Writes from listeners in auto mode are accepted (checked, wired) at once — a refused one throws to the listener — and announced after the current announcement (`_announcements`); a dependent with its own queued announcement is not also announced as a dependent
- A listener that throws undoes nothing: `emit` calls every listener and collects errors; the outermost public operation (`_operation`: set / delete / flush / deleteScope / …) throws the first once it is done, unless it threw itself
- Deleting a token cleans up its graph node and updates dependent caches; a node for a key that does not exist (a forward ref, a deleted key) is pruned once nothing depends on it
- Every existing inherited key has a graph node: one edge to its source, or its bound deps when re-bound
- Selector candidate pools are an index, not graph edges — pool membership never rejects a write
- Custom event emitter (no Node dependency) — works in browser and Node
- CodeMirror and hdr-color-input are devDependencies (editor-only)
